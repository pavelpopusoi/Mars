# Архитектура MARS

## 1. Цели

1. Принимать открытый исследовательский вопрос любой области.
2. Автономно собирать доказательства из первичных источников.
3. Синтезировать знания между дисциплинами.
4. Явно находить и разбирать противоречия.
5. Генерировать новые проверяемые гипотезы.
6. Выдавать отчёт с источниками, графом знаний и шагами, которые можно воспроизвести и проверить.

## 2. Поток данных

| # | Шаг | Агент | Вход | Выход | Параллельность |
|---|---|---|---|---|---|
| 1 | Декомпозиция | Planner | вопрос, контекст | `ResearchPlan` | — |
| 2 | Поиск | Searcher | `SubQuestion` | `SearchFindings` | до `max_parallel_searches` |
| 2б | Чтение файлов | Reader | PDF/TXT/MD/CSV/JSON пользователя | `SearchFindings` | параллельно с поиском |
| 3 | Синтез | Analyst | план, все findings | `Synthesis` | — |
| 4 | Критика | Critic | findings, синтез | `Critique` | — |
| 4a | Доисследование | Searcher | `follow_up_queries` | `SearchFindings` | если `needs_another_round` и раунд < `max_rounds` |
| 5 | Гипотезы | Hypothesis | всё выше | `HypothesisSet` | — |
| 6 | Граф | код | claims, противоречия, гипотезы | `graph.*` | — |
| 7 | Отчёт | Writer + код | всё выше | `ReportDraft` → `report.md` | — |

Шаги 3–4a образуют цикл: критик решает, изменит ли ещё один раунд поиска ответ. Цикл жёстко ограничен
`max_rounds`, чтобы стоимость была предсказуемой.

## 3. Ключевые решения

| Решение | Почему |
|---|---|
| **Оркестратор в коде, а не «агент-менеджер»** | Предсказуемый порядок шагов, понятная стоимость, легко тестировать и воспроизводить |
| **Pydantic-схемы + structured outputs** | Ответ модели всегда валиден; агенты не «ломают» друг другу вход |
| **Searcher в 2 шага**: веб-поиск → структурирование | Свободное чтение источников с цитатами, затем строгое извлечение `Source`/`Claim` только по найденным URL — меньше выдуманных ссылок |
| **Утверждения как триплеты** (subject–predicate–object) | Граф знаний строится из данных напрямую, без отдельного вызова модели |
| **Отчёт собирается кодом** из `ReportDraft` и артефактов | Таблицы противоречий, гипотез и источников всегда полные; `mars rebuild` даёт идентичный результат |
| **trace.jsonl + manifest** | Любой шаг можно проверить: что спросили, какая модель, что ответила |
| **MockLLM** | Весь пайплайн тестируется офлайн и в CI бесплатно |
| **Отказоустойчивость** | Упавший подвопрос логируется и пропускается; ретраи SDK (4) на 429/5xx; серверные фолбэки при отказе модели; защита от бесконечного `pause_turn` |

## 4. Модели и стоимость

* По умолчанию все агенты — `claude-fable-5-2`, adaptive thinking (у Fable он включён всегда), `effort` по агенту.
* Самый дорогой шаг — Searcher (N подвопросов × веб-поиск). Рычаги: модель подешевле для Searcher и Reader
  (`claude-opus-5-5`, `claude-sonnet-5-5`), `effort: low`, меньше `max_web_searches_per_question`.
* `mars estimate` и строка перед запуском дают вилку стоимости; `--max-cost` останавливает запуск выше лимита.
  Оценка грубая: она строится на типичных объёмах вызовов из `mars/costs.py`.
* Фактический расход (токены, кэш, веб-поиски, доллары) пишется в `meta.json → usage`.
* Кэширование промптов включено: повторяющийся префикс запроса читается из кэша.

## 5. Качество и проверка фактов

* Critic оценивает надёжность и независимость источников, а не их количество.
* Writer обязан ссылаться только на существующие `[source_id]`; таблица источников добавляется кодом.
* После каждого запуска код проверяет целостность: ссылки `[id]` существуют, у утверждений есть источники,
  подвопросы покрыты, гипотезы проверяемы. Итог — оценка 0–100 в `quality.json` и разделе отчёта. Это проверка
  структуры, а не истинности фактов.
* Каждое утверждение имеет `confidence`, каждый источник — `reliability` и тип (рецензируемый, официальный…).

## 6. Расширение

| Что | Где |
|---|---|
| Новый агент (например, «Статистик» или «Юрист») | класс в `mars/agents/`, схема в `schemas.py`, шаг в `orchestrator.py` |
| Свои источники (PDF, базы, arXiv, PubMed, внутренние документы) | новый метод в `LLM` или кастомные tools в `ClaudeLLM.web_research` |
| Веб-интерфейс | FastAPI вокруг `Orchestrator.run`, события шагов через `on_event` |
| Хранилище | сохранять папку запуска в S3/БД; граф — в Neo4j из `graph.graphml` |

## 7. Веб-интерфейс

`mars serve` поднимает FastAPI на `127.0.0.1:8000`. `POST /api/runs` запускает исследование в фоне,
`GET /api/runs/{id}/events` отдаёт шаги через Server-Sent Events, отчёт открывается из `/runs/{run_id}/report.html`.
Авторизации нет: сервер рассчитан на локальный запуск. Для доступа из сети поставьте перед ним прокси с авторизацией.
